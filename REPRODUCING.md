# Reproducing the numerical results

This document is the single entry point for regenerating **every numerical
result** in *"Learning Market Making with Closing Auctions"* (Graf & Mastrolia)
from a fresh clone. It covers the synthetic rough-Heston setting and the
historical S&P 500 setting, each for the discrete agent (DQN) and the three
continuous-action relaxations (DDPG, TD3, SAC), plus evaluation, regret,
figures, and tables.

The mathematical conventions are fixed by `CLAUDE.md` (author rulings D1–D20);
the audit trail is in `audit/`. Nothing under `paper/` is regenerated by these
commands — the author rewrites the paper from the saved outputs and the design
docs in `docs/`.

---

## (a) Environment setup

### Python and package

- **Python ≥ 3.10** (developed and verified on CPython **3.14.4**).
- Source layout under `src/`, package name `lmm`. `pyproject.toml` is the
  **authoritative dependency manifest**. (`requirements.txt` is a stale legacy
  pin kept only for the `legacy/` emulators; it does **not** include torch and
  is not used for the revised code.)

```bash
git clone <repo-url> Learning-Market-Making
cd Learning-Market-Making
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
pip install -e ".[dev]"              # installs lmm + numpy/pandas/scipy/
                                     # matplotlib/pyyaml/torch/gymnasium/
                                     # yfinance + pytest
```

### Torch note

All configs run on **CPU** (`algo.hyperparams.device: cpu`); a CPU-only torch
wheel is sufficient and is what `pip install -e ".[dev]"` resolves by default.
A GPU is **not** required and is not used — determinism (below) is defined for
the CPU path. If `pip` cannot fetch the torch wheel offline, install torch
separately first (`pip install torch`) and re-run the editable install.

### Hardware and rough wall-clock

CPU-only; more cores help only because the eight experiments are independent and
can be launched in parallel. Indicative wall-clock on a modern laptop CPU (Apple
Silicon), measured from steady-state per-episode timing (~0.16 s/ep synthetic
DQN, ~0.34 s/ep synthetic continuous, ~0.21 s/ep historical DQN, ~0.42 s/ep
historical continuous, incl. per-step gradient updates) plus the final
evaluation and two regret passes; see the determinism note about float
reproducibility across machines:

| Experiment (one `run_*.sh`)                      | Episodes        | Approx. wall-clock |
|--------------------------------------------------|-----------------|--------------------|
| synthetic_rough_heston, DQN                      | 1000            | ~3–4 min           |
| synthetic_rough_heston, DDPG / TD3 / SAC (each)  | 1000            | ~6–8 min           |
| historical_sp500, DQN (5 tickers, serial)        | 500 × 5         | ~10–13 min         |
| historical_sp500, DDPG / TD3 / SAC (5 tickers)   | 500 × 5         | ~18–23 min each    |

> Episode budgets were tuned 2026-06-15 (synthetic 2000→1000, historical
> 1000→500; all four algos plateau well before, AUDIT §F.3).
> **Full reproduction ≈ 2–3 CPU-hours single-threaded** (4 synthetic + 20
> historical training runs, plus final evaluation at 100 seeds each and the two
> regret passes). Launching the eight `run_*.sh` in parallel brings wall-clock
> down to roughly the slowest single launcher (~23 min, a historical continuous
> run). The `--smoke` pipeline (below) completes in ~2 min and exercises every
> code path end-to-end.

## (b) Exact command sequence (fresh clone → all results)

All commands are run from the repo root with the venv activated. The canonical
**master seed is 42** (the config default; pass `--seed N` to change it — runs
are named with the effective seed, e.g. `dqn_seed42`).

### Step 0 — Data

The historical experiments read the **frozen committed input**
`legacy/data.csv` (real S&P 500 1-minute mids, 2025-12-31 14:30–17:00 ET,
normalized to 100 at session start; ruling D13). It is the default in
`configs/historical_sp500.yaml` and the source of truth — **no command is
needed** to reproduce the paper.

> **Do not run the loader to reproduce the paper.** yfinance only serves
> 1-minute bars for a **~30-day lookback**, so the paper's `2025-12-31` session
> can no longer be fetched — `--date 2025-12-31` now fails loudly with
> `yfinance returned no 1m bars ... must be within the last 30 days` (by design;
> see `data/README.md`). The frozen `legacy/data.csv` above is the paper's data
> and is used automatically.

The loader is **only** for building a *new* (different) dataset on a **recent**
date. Two real-world constraints shape the command (both enforced by the loader,
which fails loudly otherwise):

- **Date:** within yfinance's ~30-day 1m lookback (older dates → no bars).
- **Session window inside regular trading hours (09:30–16:00 ET).** The paper's
  14:30–17:00 window has a post-close tail (the auction is a *modeling*
  construct, backed by the frozen CSV) — real intraday bars stop at the 16:00
  close, so that window is always missing its last hour. Use a window that fits
  in RTH and still spans exactly `clob_minutes + auction_minutes + 1 = 151`
  one-minute bars. The example below uses **13:30–16:00** (CLOB 13:30–15:30,
  auction 15:30–16:00, ending at the real close). `--fill ffill` patches the
  single 16:00-labelled bar (yfinance labels the last RTH minute `15:59`).

The exact command below is verified end-to-end (writes 151 rows + a metadata
sidecar; one forward-filled minute, the close):

```bash
# OPTIONAL — produces a NEW dataset, NOT the paper's.
# Edit RECENT to a recent trading day within yfinance's ~30-day 1m lookback.
RECENT=2026-06-12
python3 -m lmm.data.load_yfinance_data \
    --tickers CAT PG GOOGL JPM MSFT \
    --date "$RECENT" --interval 1m \
    --session-start 13:30 --session-end 16:00 \
    --clob-minutes 120 --auction-minutes 30 \
    --normalize first=100 --fill ffill \
    --out "data/mid_prices_$RECENT.csv"
# then set configs/historical_sp500.yaml: midprice.historical.{csv_path,date,symbols}
```

### Step 1 — One-shot full reproduction

```bash
scripts/reproduce_all.sh --seed 42
```

This trains, evaluates (with CRN), and computes AS + TWAP regret for all eight
experiments, then regenerates every figure and table. The eight experiments are
{synthetic, historical} × {DQN, DDPG, TD3, SAC}; the **historical** setting
loops the five paper tickers `MSFT JPM PG GOOGL CAT` per algorithm, so the full
run is **4 synthetic + 20 historical = 24 training runs**.

### Step 2 — Equivalent explicit per-experiment commands

`scripts/reproduce_all.sh` is exactly the following (each `run_*.sh` does
train → evaluate → regret(as) → regret(twap) internally):

```bash
# Synthetic rough-Heston (rough_heston mid; 1000 episodes)
scripts/run_synthetic_dqn.sh   --seed 42
scripts/run_synthetic_ddpg.sh  --seed 42
scripts/run_synthetic_td3.sh   --seed 42
scripts/run_synthetic_sac.sh   --seed 42

# Historical S&P 500 (frozen legacy/data.csv; 500 episodes; 5 tickers each)
scripts/run_historical_dqn.sh  --seed 42        # add --symbol MSFT to restrict
scripts/run_historical_ddpg.sh --seed 42
scripts/run_historical_td3.sh  --seed 42
scripts/run_historical_sac.sh  --seed 42

# Regenerate all figures/tables from the finished runs (per-run + combined)
scripts/make_all_outputs.sh
```

### Step 3 — Raw CLI form (one experiment, by hand)

The launchers wrap these module entry points (console scripts `lmm-train`,
`lmm-evaluate`, `lmm-regret`, `lmm-make-figures`, `lmm-make-tables` are
equivalent). Example for synthetic DQN at seed 42:

```bash
RUN=results/synthetic_rough_heston/dqn_seed42

python3 -m lmm.experiments.train \
    --config configs/base.yaml \
    --config configs/synthetic_rough_heston.yaml \
    --config configs/algo/dqn.yaml \
    --run-name dqn_seed42 --seed 42

python3 -m lmm.experiments.evaluate --run-dir "$RUN" --trace-episodes 1
python3 -m lmm.experiments.regret   --run-dir "$RUN" --benchmark as
python3 -m lmm.experiments.regret   --run-dir "$RUN" --benchmark twap
python3 -m lmm.experiments.make_figures --run-dir "$RUN"
python3 -m lmm.experiments.make_tables  --run-dir "$RUN"
```

Historical runs add `--symbol <TICKER>` to both `train` and `evaluate`, and the
run name carries the ticker (e.g. `dqn_MSFT_seed42`). Cross-algorithm combined
figures/tables are produced by passing all sibling run dirs to one
`make_figures`/`make_tables --out results/<setting>/_combined/...` call (this is
what `make_all_outputs.sh` does automatically).

### Step 4 — Fast end-to-end smoke (CI / sanity)

```bash
scripts/reproduce_all.sh --smoke --symbol MSFT --seed 42
```

Tiny episode counts (4 train / 3 eval), historical restricted to one ticker;
exercises the whole train→eval→regret→figures→tables pipeline in a few minutes.

## (c) Artifact → path map

Everything lands under `results/<experiment_name>/<run_name>/` (git-ignored).
`<experiment_name> ∈ {synthetic_rough_heston, historical_sp500}`;
`<run_name>` is `<algo>_seed<seed>` (synthetic) or `<algo>_<ticker>_seed<seed>`
(historical).

### Per training run

| Artifact | Path | Notes |
|---|---|---|
| Resolved config | `<run>/config_resolved.yaml` | full merged config actually used |
| Master seed | `<run>/seed.txt` | the integer master seed |
| Git provenance | `<run>/git_sha.txt` | commit the run was produced at |
| Per-episode metrics | `<run>/metrics.csv` | schema in `docs/metrics_schema.md` |
| Run log | `<run>/logs/run.log` | |
| Checkpoints | `<run>/checkpoints/{initial,best,final}.pt`, `ckpt_ep<N>.pt`, `ckpt_ep<N>_trainstate.pt` | `initial` = untrained net; `best` = best eval; `final` = end |
| Eval records | `<run>/eval/records.csv` | per-episode, all policies, CRN |
| Eval metadata | `<run>/eval/metadata.yaml` | |
| Regret (AS) | `<run>/eval/regret_as.csv` | PRegret(T) vs AS benchmark |
| Regret (TWAP) | `<run>/eval/regret_twap.csv` | PRegret(T) vs TWAP benchmark |
| Episode traces | `<run>/eval/traces/{dqn,as,twap,initial}_ep<i>.csv` | per-step anatomy for figures |

### Generated figures (per run under `<run>/figures/`, and combined under `results/<setting>/_combined/figures/`)

Each figure is written as both `.pdf` (for LaTeX) and `.png`.

| File | Replaces in paper | Source |
|---|---|---|
| `training_diagnostics.{pdf,png}` | `fig:training_analysis` (loss + returns; `fig:training_loss`) | `metrics.csv` |
| `regret_curve.{pdf,png}` | `fig:regret_training` (DQN-vs-GLFT regret) | `eval/regret_*.csv` |
| `episode_anatomy.{pdf,png}` | `fig:episode-2000` | `eval/traces/dqn_ep0.csv` |
| `benchmark_anatomy.{pdf,png}` | `fig:episode-2000-bm` (benchmark behaviour) | `eval/traces/{as,twap}_ep0.csv` |
| `eval_distributions.{pdf,png}` | final-evaluation distributions | `eval/records.csv` |
| `algorithm_comparison.{pdf,png}` | **new** (cross-algorithm DQN/DDPG/TD3/SAC) | all runs' `eval/records.csv` |

### Generated tables (per run under `<run>/tables/`, and combined under `results/<setting>/_combined/tables/`)

Each table is written as both `.tex` (booktabs) and `.csv`. Reported returns are
**undiscounted** episode sums (stated in each caption; objective conventions in
`CLAUDE.md`).

| File | Replaces in paper | Setting |
|---|---|---|
| `eval_summary_final.{tex,csv}` | `tab:eval_summary_final` | synthetic group |
| `dqn_results_full.{tex,csv}` + `dqn_results_improvements.{tex,csv}` | `tab:dqn_results_full` | historical group |
| `params_generative.{tex,csv}` | `tab:params_generative` | from resolved config (author regenerates the paper table from this) |
| `params_midprice.{tex,csv}` | mid-price-model provenance | supporting |
| `hyperparams_<algo>.{tex,csv}` | **new** (RL hyperparameters; supports the Sec. 4 rewrite) | per resolved algo config |

## (d) Determinism statement

Seeding is rebuilt from scratch (ruling D10) in `src/lmm/utils/seeding.py`: one
private `numpy.random.Generator` **per component**, spawned from a single master
`numpy.random.SeedSequence`; torch is seeded from the same master seed. **No
global `np.random.*` / `random.*` state is ever touched.** Per-component stream
identity is a deterministic function of the master seed and the sorted component
names.

**Bit-reproducible** — for a **fixed config + master seed on the same
machine/torch build**, every saved numeric value is identical across processes
and reruns: `metrics.csv`, `eval/records.csv`, `eval/regret_*.csv`, and the
checkpoints. The **only** non-reproducible field is the `wall_clock_s` timing
column of `metrics.csv` (verified in Phase 8: two same-seed training runs gave
byte-identical `metrics.csv` after dropping `wall_clock_s` — identical SHA-256).
Asserted by `tests/test_determinism.py`.

**Torch determinism flags** set in `seed_everything`:

```python
torch.manual_seed(master_seed)
torch.use_deterministic_algorithms(True, warn_only=True)
# if CUDA present (not used by these configs):
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```

**What varies** — wall-clock timing; and floating-point results **across
different machines, BLAS/LAPACK builds, or torch/numpy versions** (IEEE-754
reduction order differs). All configs pin `device: cpu` to keep the reference
path deterministic; cross-machine bit-identity is *not* guaranteed, but the
qualitative results and seeded relative comparisons (CRN regret) are stable.
The legacy emulators in `legacy/` use a different (global-RNG) architecture by
design and are **not** seed-comparable to the revised env — see
`audit/BEHAVIOR_CHANGES.md`.
